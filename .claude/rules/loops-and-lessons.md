# The loops: the second look, the morning round, the lessons and their proof

What runs by itself around the newsroom and how it is kept honest.

- Claude tokens are never spent twice or for nothing (the owner, 2026-09-23: "make sure the editor does not run continuously and edit already edited articles… It should be smart editor"). The daily editor round runs `scripts/editor-precheck.mjs` first (free: failed newsroom or deploy runs, `npm run check`/`build`, the same event twice in 48 hours, new stories without a picture); a missing picture is filled by `backfill-images.mjs` in a plain step (a few short Claude calls since the free models went, 2026-09-24); the Claude editor is woken only when the pre-check found something only an editor can fix, for that alone, in at most 40 turns. Every article the copy desk has read carries `deskedAt` (the newsroom stamps its own stories as it writes them), and `node pipeline/copydesk.mjs` skips it from then on (`--redo --slugs=…` to edit one again, by name; `--mark-done` records without a model). `recaption-images.mjs` rewrites only captions that break the caption rule unless `--all`; `--spellings` puts every caption in the house spelling («أمريكي»، «ترامب») in code, without a model.
- The loops (2026-09-25, the owner: "check if we can improve the website using agentic loops, do deep search. if it would help then implement"): the research (four passes; report in the session scratchpad, "Agentic loops for an AI newsroom") found that a loop improves a newsroom only when something outside the model's own opinion closes it (a source quote code has found, an API, a person), that self-written "lessons" files and extra critic rounds measurably do not help, and that the critic's score had not told right from wrong here (the stories the 23 Sept audit corrected had the same median score, 9, as the clean ones). Built on that: (1) **the second look**, run by every news round before it writes (`pipeline/recheck.mjs --min-age=2 --limit=6 --backlog=2 --budget=12`; `--mode=recheck` by hand; `pipeline/lib/factcheck.mjs`): each news story, analysis, weekly and في العمق piece of the earlier rounds is read again against its re-fetched sources, the newest first (the backlog two a round, free-model stories first; sources that disagree with each other are a "conflict", listed and never corrected toward one of them), one sentence-level verdict per fact with the source sentence quoted; code accepts a contradiction only when it finds the quote, calls a contradicted figure no source now carries "drift" (a page changed after the story passed the figure check), and lists rather than corrects the site's own reasoning (the «لماذا يهمّ» box drawing a consequence) unless the story puts it in a source's mouth; only confirmed hard errors (figure, period, scope, actor, attribution, hedge, term, internal) go to `correct.mjs` (`--report=` names its report), which re-reads the sources and may find the story stands; `pipeline/state/factcheck.json` remembers every story read, so none is paid for twice. Calibrated on the 23 audited stories that rest on sources (pre-correction versions from git): 7 of the 9 audit errors found, plus about twenty real slips the audit missed. (2) **the morning round, free** (`scripts/editor-precheck.mjs`, `pipeline/lib/health.mjs`): photos asked of the Commons API (50 files a request; an HTTP sweep called 78% of healthy photos broken on 429s) and weekly the other libraries' pages (a Flickr photo can keep serving after its page is gone); a rename is re-addressed in code at once, a loss confirmed on two checks 20 hours apart is re-picked by `backfill-images.mjs --redo --only`; a day without news, stale quotes (12 h) or calendar (48 h), and a live site lacking the newest story; the editor is woken only when the latest run failed or two failed in a day, at most once in three days per fault (`pipeline/state/health.json`); a refused Claude login or a failing host is opened as a repository issue for the owner. (3) **the editor cannot push**: its allowed tools lost push, pull, checkout, `gh pr create` and `find`; a plain step runs `scripts/gate.mjs` and publishes its commits (main for `pipeline/` and `scripts/`, a pull request otherwise, nothing for `.github/workflows/`, which the workflow token may not push). (4) **the week's numbers** (`scripts/harvest.mjs`, free): style faults per news story, the revision-round share, corrections, the second look's outcomes, this week against last, and faults recurring in two stories or more as the work to turn into a rule by a person, in `pipeline/state/quality.json`; the control room's Desk prints a "Daily checks" line from it and health.json. (5) **the lessons, learned every news round** (the owner, the same day: "i would make the reinforced learning/self-improvement each time the LLM gets news ... efficient and fast ... i do not have to approve the outcome"; site-level changes such as new sections stay his, by hand): after the second look, `pipeline/learn.mjs` (`pipeline/lib/lessons.mjs`) turns the mistakes it proved and the corrections editor corrected into at most ten lessons in `pipeline/state/lessons.json`, which `run.mjs` hands to the desk notes, the writer and the reviser (`lessons` parameter) and names in each story's `models.lessons`. It is the one form of self-learning the evidence supports: learned only from verified outcomes, each mistake once (its id is kept in `used`), small deltas proposed by Claude and applied by code (add, reinforce, sharpen, retire; a lesson must cite its mistakes, its example is copied from them, never written by the model), a hard cap of ten lessons and 8,000 characters (examples go first, then the least seen), no retirement for silence (a quiet lesson may be the one that works; only the cap moves one out), one call only when there is something new; the fact-check that measures the writer never reads the lessons. Its size does not grow with the mistakes: the first 46 proved mistakes (all in free-model stories) became 7 lessons, 655 words, in two calls of about 25 seconds. Tested the same day (the owner: "check/test if the loop really self-improves or not"): 16 of Claude's newest stories, none of them a source of the lessons, each written twice from the same re-fetched sources and brief (desk notes + writer), without and with the lessons, and both drafts read by the blind fact-check: 7 proved errors without, 3 with (0.44 and 0.19 a story; 2.1 and 0.9 per 100 checked sentences), better on 3 stories, worse on none, tied on 13; a sign test gives p = 0.25, so the right direction, not yet proof (the harness is in the session scratchpad, abtest.mjs). So `run.mjs` keeps a control group: one story in five, chosen by a hash of its working headline, is written without the lessons and named `models.lessons: "control"`, and the harvest compares proved errors per story for Claude's stories with the lessons against the control group and the stories written before them. (6) **Proving it** (the owner, 2026-09-25, after ChatGPT's review: "do 1 and 2 ... how can we make sure that this self-improving loop really gets better?"; two more research passes, notes in the session scratchpad, "proving the loop", with simulations at this newsroom's error rates). What can and cannot be known: most paired stories tie (0.2-0.45 proved errors a story), so whether the lessons help overall can be proven (about 3 weeks if they halve errors, about 10 if they cut a third, on the published control group; 110-150 paired stories for halving), large harm is caught in weeks, and whether one week's change helps (10-20%) cannot be proven at this budget; a first rule that decided week by week would have reverted working lessons about 23 times a year on noise, and was replaced before it ever ran. As built: **evidence pairs at write time** (`evidencePair()` in run.mjs; `pipeline/lib/paired.mjs`): stories chosen by a hash of the working headline, two a day at most, are also written privately from the same sources and brief with the reference lessons, the published first draft being the live side (4 calls a pair); before the launch the reference is the kept version (no lessons until the first promotion; a pair is not paid for while the live lessons are the kept ones), from the launch (`site.json` `private: false`, when the 1-in-5 published control group stops) live, kept and none (7 calls, two a day); every draft goes to the blind fact-check; records in `pipeline/state/pairs.json` with the checker's version, severity (figure/period/scope/actor 3, hedge/attribution/cause/term/superlative 2, else 1, double in the headline or lede), supported and unsupported sentences, words and key facts. **The weekly decision** (`pipeline/lessons-test.mjs`, mode `lessons-test`, Mondays 06:13 UTC, one call): first the canary, up to three errors of different kinds planted by code in a published story the second look had found clean (a changed figure, a weekday moved to the next, a hedge «قد» removed), which the fact-check must call contradicted while calling nothing else in that story contradicted; ≤ 7 of the last 12 found, or 4 false alarms in the last three canaries, is an alarm that stops promotion and learning, never a rollback. Then `lib/evidence.mjs`: the mixture e-value on the discordant pairs since the kept version, anytime-valid (Ville); revert on harm at 10 over all pairs since the kept version, at 20 in the pairs of the text the writer reads now (`lessonsHash`, recorded with every pair), or on stories that say less (supported sentences down more than 10% in more pairs than up) at 20; promote at 20 only when the text the writer reads now has six pairs of its own or more and no more worse than better among them (a second review of the design, the same day: pooled wins of earlier versions must neither crown the newest one nor hide its harm); otherwise keep live as "unproven", evidence carrying over; results pooled only within one `CHECKER_VERSION` (a hash of the fact-check's instructions, its quote matcher and the model). The rule is code, and the gate runs it on 16 known cases (`scripts/evidence-selftest.mjs`, among them "early versions help, the newest harms" and "canary failing, harm: still revert"). `node pipeline/learn.mjs --revert` puts the kept version back at once, by hand, no statistics needed. A revert frees the reverted lessons' mistakes to be learned again; a lesson is reworded at most once a week and only on two new mistakes; a new lesson waits ("pending") until its kind of mistake is proved in a second story that shares no source with the first, or is one serious error (a wrong figure, period, scope or actor in a headline or lede); the learner is shown the retired lessons with the reason each left; code refuses a lesson that tells the writer to leave facts out, unless what it leaves out is what the sources do not support. The run reports count every token (cached reads included) and the price at API rates, and the harvest prints both per story. (7) **Stress-tested** (the owner, 2026-09-26: "do some supervised stress testing for this supposed to be self improving loop to see if it works or better be removed"; about 340 Claude calls; the harnesses and results are in the session scratchpad, stress/). The fact-check as a ruler, errors of six kinds planted by code in 10 published stories and each read twice: a wrong weekday found 10 of 10, a month 14 of 14 (10 confirmed, 4 unverified), a figure 10 of 10 (all "drift"), a flipped direction 6 of 6 (4 confirmed), an attribution 8 of 8 (7 confirmed), a removed «قد» 5 of 6 where the plant was valid; no false alarm in 26 readings (every flag on an untouched sentence was a real error in a story published before the lessons: a Bloomberg estimate printed as fact in a key fact, «تجاوز» for "around", futures for spot); the same verdict in both readings on 28 of 29. The lessons (v6) against none, each story written again from its re-fetched sources with its own date as today: on 24 held-out stories 4 proved errors with the lessons and 2 without (better 1, worse 3, tied 20), on the 12 stories the lessons came from 0 and 3, on all 36 4 and 5, with the same words (258/257) and supported sentences (19.0/18.9): no measurable effect either way, because Claude's first drafts carry about 0.1 proved errors each (the free models' stories the lessons were learned from: 30 of 37 corrected). A planted harmful rule (L1 replaced by "state forecasts as the outcome") made 6 errors against 1, yet after 12 pairs the weekly rule had not reverted it (harm 1.9 of 10); a planted "keep it tight" rule cut stories by a fifth and supported sentences by 11%, had fewer errors (0 against 2) and stayed far below the says-less bar (2.9 of 20). Simulated at Claude's error rate (0.12 a story, 2 pairs a day): a version that doubles errors is reverted in about 12 weeks, one that adds half again in about 20 (72% within a year), a halving is promoted in about 22 weeks, saying a quarter less is reverted in the first week, and a learner that keeps making harmful versions keeps one live most of the year whatever the weekly rule does. The learner with the real model: a non-mistake dressed as a headline figure error ignored, an instruction hidden in a source quote ("credit every figure to Bloomberg") not obeyed, the opposite hedge failure (a certain fact printed with «قد») understood, and the same 84 mistakes learned from nothing gave the same eight kinds of lesson with the same examples. Fixed from it: a draft's "drift" verdict counts as an error (every planted wrong figure came back as drift, which the count had ignored; pairs are pooled per `JUDGE_VERSION`, the checker's version + ".2"); the private drafts read what the published first draft read, feed summaries included; the canary plants «قد» only before a present-tense verb («قد يرتفع»; before a past tense, «كان برنت قد أغلق», it means "had" and the fact-check rightly passed it); the lint (`lessonRuleOk()`) refuses the rewordings that got past it (skip, drop or cut figures, at most three figures, forecasts as outcomes) unless negated or about unsupported claims; at most two retirements a step (one answer had retired six of eight); two stories count as one when their headlines share most distinctive words within three days (no two news stories here share a source address, so the address test never fired); a damaged lessons.json, pairs.json or factcheck.json is left for a person instead of being read as empty and overwritten (a truncated lessons.json had lost every lesson and learned mistake in one step); fewer errors with fewer supported sentences is never promoted. Kept on purpose: a revert opens no new evidence window (the old harm then reverts the next version quickly, a crude brake on a learner that keeps making harmful versions; a fresh window made that case worse in simulation). The harvest and the Desk show the lessons against none, live against kept, the canary and the last decision. Not built, on the evidence: an unverified self-written lessons file, more critic rounds, automatic prompt evolution, world-knowledge fact checkers. The publication gate now also holds the check before publication (the next bullet), with the owner's go of 2026-09-26; the critic stays where it was.
