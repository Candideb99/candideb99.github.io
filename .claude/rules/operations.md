How the site is run. Dated entries; where two differ, the later one stands.

- Before handing off: `node scripts/gate.mjs` must pass (every pipeline and tool script parses, `astro check` has no errors, `npm run build` succeeds); it records a pass in `.gate/pass.json`, and a Stop hook (`.claude/settings.json` → `scripts/gate-hook.mjs`, this project's sessions only) holds a turn once when a covered file changed since. Added 2026-09-23 after an implicit-any error in a finished-looking change was caught only by a hand-run check; tested on a real type error, which it failed. Run `npm run newsroom:dry` to test pipeline changes without publishing. Since 2026-10-23 it also fails on a name a script uses but never defines (TypeScript over the JavaScript, `scripts/tsconfig.names.json`, about 4 s; every other type message is ignored): the multi-provider rewrite of 17 October had dropped `const refusedLogin` from `scripts/editor-precheck.mjs`, which still parsed, and the daily editor's round died on a ReferenceError seven days running, so no failed run, lost photo or refused login reached the owner. The definition is back, and `llm.mjs` now marks a refused credential of any provider `login=refused` in the run log (the Claude CLI's «disabled Claude subscription access» of 1-17 October counts as one), which the round reads.

- The news clock, 2026-11-20 (the owner, on another session's remark that GitHub starts scheduled runs late and skips some, which "you don't notice" here thanks to the three-hourly line and the fill-in: "if yes then fix it at the source"). - The pieces on the clock, and the pause, the same night (the owner: "move the daily pieces onto the clock too, also did you account for the fact that I might manually stop publishing by pausing the news room? so nothing goes wrong or hallucinates. also by doing these fixes we optimized and minimized claude token usage while maintaining high quality articles?"). (1) **Every newsroom run comes from the clock**; newsroom.yml has no schedule (a line there would write a piece beside the clock's) and names each run by its mode (`run-name: "Newsroom: <mode>"`), which the clock reads. `PIECES` in news-clock.mjs holds the old lines' times; a piece is due from its time for `WINDOW` (8) hours, once (started since its time, by the run list or a report), on its days; at each firing: nothing while a run goes or waits, then a piece whose window ends within `URGENT_H` (2) hours, then a news round, then the earliest piece. A failed run counts as started (never retried hourly, which would pay twice); a cancelled or skipped one did nothing and does not. (2) **The pause was not airtight**: it only set `KHAZENDAR_PAUSED`, read when a job starts, so a run already writing published up to an hour after Pause. `setPaused()` (desk-lib.mjs, the control room's /pause) sets the switch, then cancels every run of the newsroom, the clock and the editor not completed (a run commits only in its last step); Resume clears it and re-enables news-clock.yml and editor.yml (GitHub switches a public repository's schedules off after 60 days without activity). After Resume a piece runs only inside its window, so nothing missed is written late, and the pieces' own floors (three news stories of 72 hours for an explainer or an analysis, five of the week for the review; run.mjs) stop a piece without material before any model call. (3) **The morning round would have cried stall after a pause**: it counted 24 hours from the newest story, and skipped runs as runs completed; with the clock a paused newsroom leaves no newsroom runs at all. `quietHours()` counts from the later of the newest story and the clock's newest skipped run (the pause), and the runs since leave out cancelled and skipped ones (editor-precheck.mjs, which now reads news-clock.yml's runs too, so a failing clock is a finding). (4) **Tokens: these fixes cut nothing; they hold the spend.** From the run reports (API-rate equivalents, the plan's meter not read): a news round $12.73 median (14 rounds, 89 calls in one: writer 19, critic 20, picture desk 30 at $3.16, desk 14), the second look $0.27, an explainer $4.12, an analysis $3.94, an idea $3.91, the reports desk $2.43; every news round published something. News is about four fifths of the day's spend, so the gap is the dial: `GAP.day` 4.5 hours gives 4.05 rounds a day (simulated, pieces on the clock, delay 4/9/12 hours) against 4.1 measured before, the longest daytime wait 5.5 hours against 7; 4 hours gave 4.3 (about 6% more), 5 hours 3.8. The pause's cancel can waste the part of a run already done; the stall fix spares a paid editor session after each long pause. (5) Tested: `scripts/news-clock-selftest.mjs` 31 cases (the fill-in's script fails the 5 offline news cases); live and read-only against the real run list at 19:32 UTC (news, 7.7 hours after the 11:49 round), 20:30 and 21:10 (the day's analysis, its window closing at 22:07), the next morning (news before the explainer). The editor's round stays on its own one-slot line (07:17 UTC, about nine hours late; it publishes nothing). Not seen running: the newsroom was paused (16:04 UTC) when this went live.
