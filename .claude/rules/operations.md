# The control room, the gate, deploys, schedules and security

How the site is run. Dated entries; where two differ, the later one stands.

- Before handing off: `node scripts/gate.mjs` must pass (every pipeline and tool script parses, `astro check` has no errors, `npm run build` succeeds); it records a pass in `.gate/pass.json`, and a Stop hook (`.claude/settings.json` → `scripts/gate-hook.mjs`, this project's sessions only) holds a turn once when a covered file changed since. Added 2026-09-23 after an implicit-any error in a finished-looking change was caught only by a hand-run check; tested on a real type error, which it failed. Run `npm run newsroom:dry` to test pipeline changes without publishing. Since 2026-10-23 it also fails on a name a script uses but never defines (TypeScript over the JavaScript, `scripts/tsconfig.names.json`, about 4 s; every other type message is ignored): the multi-provider rewrite of 17 October had dropped `const refusedLogin` from `scripts/editor-precheck.mjs`, which still parsed, and the daily editor's round died on a ReferenceError seven days running, so no failed run, lost photo or refused login reached the owner. The definition is back, and `llm.mjs` now marks a refused credential of any provider `login=refused` in the run log (the Claude CLI's «disabled Claude subscription access» of 1-17 October counts as one), which the round reads.
- Deploys: pushing `main` to `Candideb99/candideb99.github.io` builds and publishes via GitHub Pages; the newsroom workflow runs on a cron and commits to `main` itself. GitHub's own publish step can stall at «syncing_files» and stop after ten minutes with "Timeout reached, aborting!" while the build and Cloudflare Pages succeed (twice on 2026-11-06, 16:54 and 20:43 UTC, GitHub's status page reporting no fault): not ours; re-run the failed job (`gh run rerun <id> --failed`) or let the next deploy publish.
- Scheduled automation: `.github/workflows/editor.yml` (daily Claude editor) and `agent.yml` (issue-triggered) both run on the owner's subscription and are gated on the repository variable `KHAZENDAR_EDITOR=1`; `KHAZENDAR_PROVIDER=claude` additionally routes the newsroom's writing to it. Both pass the workflow's own `github_token` (the Claude GitHub App is not installed; its token exchange failed every round from 2026-09-22), and the editor's `--allowedTools` lists exactly the commands its round names: the action allows no shell command by default, and the first rounds died on refused calls. The editor writes `editor-report.md` (gitignored), which the last step publishes as the run summary; the first round that ran to the end was 2026-09-23.
- The morning fill-in (the owner, 2026-10-25: "why there are no new articles published in the last 3 hours? is the schedule running normally or is there a bug?", then "add the extra morning news triggers with the 2.5-hour guard, and measure it over the next few days"). No bug: from 21 September to 25 October GitHub gave each cron line a run about every six hours (median) whatever it asked for, the three-hourly news line and the two-hourly deploy line alike, while separate lines fired independently. So the news line left the same hole every morning: no news story from about 05:30 to 12:00 UTC (08:30–15:00 in Riyadh), a median morning wait of 6.4 hours in the week before. `.github/workflows/news-fill.yml` asks for morning slots on two lines of its own (02:13–09:43 UTC, since GitHub fires them up to five hours late), and `scripts/news-fill.mjs` starts a news round (`gh workflow run newsroom.yml -f mode=news`) only inside 06:00–10:30 UTC, only when the last news round started 2.5 hours ago or more (the newest news report in `pipeline/runs`), and never while a newsroom run is running or waiting (GitHub keeps one waiting run per concurrency group and cancels the older, which may be the day's explainer). The three-hourly line itself is unguarded: in 162 rounds it fired under 2.5 hours apart 7 times (2.37 at least), each the late evening's second round, which a 2.5-hour guard would have cut. `node scripts/cadence.mjs` prints per UTC day the rounds by trigger (a fill-in round is a workflow_dispatch by github-actions[bot]), the fill-in's firings, stories, the longest wait and the morning wait, and the week before against the days after. Judge it on three full days; if the median morning wait does not fall well below 6.4 hours, delete the workflow.
- Security (the owner, 2026-10-23: "protect my website and control room against hacking and against stealing my APIs"). A scan of every git object (all branches, both remotes, unreachable ones), commit messages and working files found none of the laptop's keys anywhere, and no key pattern. Found and fixed: (1) **the control room obeyed any web page** open in the owner's browser (it checked nothing but `/accounts`, and `body()` reads JSON whatever the content type), and `/writers` put the model name it was sent into a shell line, so a page could publish, unpublish, swap the keys or the AdSense ID, or run any program on the laptop. Now the door in `control-room.mjs` (`doorCheck()`): a token drawn at every launch goes with every request (the page wraps `fetch`; the chat's stream alone takes it as `?t=`), the Host must be the desk's own (DNS rebinding), a request another site sends is refused (Origin, `Sec-Fetch-Site`), POSTs must be JSON, and the page cannot be framed; a tab left open from before a restart reloads itself once. Every command runs without a shell (`exec()`, `runJob()` steps; npm and npx keep one with fixed arguments), model names and the thinking budget are checked, .env takes no line break, the AdSense ID and the verification code must look like one, a link from a story's data opens only http(s) inside the desk, the chat runs without the newsroom's keys and may not read `.env` or edit `.github/workflows/` (`BLOCKED_TOOLS`, tested live: both refused), and «Publish changes» never sends a workflow. 40 hostile requests against a test instance were refused, with the desk working. (2) **A story's body could carry markup**: Astro passes raw HTML through, so a source that talked the writer into a `<script>` would have run in readers' browsers (9 of 10 hostile bodies did, in the site's own pipeline). `src/lib/remark-safe-markdown.mjs` drops raw HTML and non-web addresses, and `src/lib/safe-url.mjs` `safeHref()` guards the sources, photo credits and calendar links; no published body used either, and 1,091 of 1,093 built pages came out identical (the other two, the front page and /tags/, moved with the clock). Headlines and boxes were already escaped (`isolateNumbers()`). (3) `public/_headers` sends framing, plugin, base, form, permission and HTTPS rules on every page; no script allowlist, which AdSense would break. (4) GitHub: a ruleset forbids force-pushing or deleting main (the newsroom only fast-forwards), Dependabot alerts are on, outside contributors' workflow runs wait for approval, and `anthropics/claude-code-action`, the one third-party action and the one holding the Claude token, is pinned to a commit (bump it there, in editor.yml and agent.yml). (5) `npm audit fix` cleared 9 of 14 advisories (Astro 7.3.1 → 7.4.2, sharp, which the picture desk runs on images from the web, vite, follow-redirects…); the rest sit in jimp/potrace, used only by `npm run brand` offline. Its build changed only the minifier's whitespace: 1,089 of 1,091 pages kept the same text (spacing included), links, pictures, scripts and styles, the same two moving with the clock. Astro 7.4 refuses Node below 22.23.4 (the security release of 2026-10-20); "22" had resolved to the runners' cached 22.23.3 and the first deploy failed, which the local gate, on Node 24, could not see. `.node-version` now holds the exact release, read by Cloudflare Pages and by every workflow (`node-version-file`): raise it there, once. (6) The Gemini key goes in a header, never in an address that an error could print into a public run report. Already sound: secret scanning and push protection on, default workflow token read-only, no `pull_request_target`, the agent owner-only, the newsroom's Claude calls without tools, the ChatGPT tokens masked in logs.
- The control room, 2026-11-10 (the owner: "debug the control room and fix bugs at the source"). Driven button by button on a scratch clone (its own fake `pages` remote, no keys, `gh` off the PATH, a stand-in for Claude Code), each fault reproduced there before it was fixed; ten self-test cases drive a real control room in a scratch repository and fail on the old code. (1) **The light cried wolf**: it read the deploy.yml run, which publishes the GitHub Pages mirror, and that evening GitHub's publish step stalled after a clean build, so the desk said THE SITE IS NOT UPDATING while khazendar.pages.dev (Cloudflare, the live site) carried the newest story. `liveSite()` now asks the live site for the newest story the remote's branch holds (committed 20 minutes ago or more; 200 is current, 404 behind) and `siteLight()` (scripts/desk-lib.mjs) decides: green; amber when only GitHub's publish step failed after a clean build; red when the live site is behind or the build itself failed (the host builds the same pages). (2) **gh's words were read, not its exit code**: signed out, gh prints «To get started with GitHub CLI…», none of the words looked for, so the desk said «gh is signed in», showed its own defaults as the cloud's state and answered «Paused» to a pause that never reached GitHub. `runProgram()` answers `{ ok, out }`; health, Pause, the review switch and Apply read `ok`, and with GitHub unreachable the desk says the cloud's state is unknown. (3) **A failed push left a story "live"**: a publish whose sync or push failed kept its commit here, the story was no longer a draft, and nothing offered to send it. `/api/state` counts the commits `pages/main` lacks (`unsent`), and the Desk shows them with «Send to the site» (`/push`, which runs the gate first when a waiting commit touches anything but stories, state and site.json). (4) **The chat**: a Claude Code program gone since the desk started (an update replaces it) raised an unhandled `error` and stopped the whole control room; the box and Send stayed locked after a refusal, an error, a crash or Stop (unlocked only on a finished answer); a run that ended in an error (the plan's limit) showed «finished in 0s» and no reason; a session id was kept from a run that never started. Every ending now sends `idle`, the reason is shown, and the conversation is resumed only once Claude Code has named it. (5) **The page**: the Desk's «Latest on the site» table had a header and no rows since it was built; every poll rebuilt the tables, so an open ⋯ menu or sources list shut every 20 seconds (`setHtml()` replaces a block only when it changed); the Stories list stopped at 200 of 592 silently (October's 210 could not all be reached: «Show more»); a story's time read «Tue 10:25 AM» whatever its week (`fmtStory()`). (6) Smaller: a draft's handout photograph answered 401 on its card (served from `/photos/handouts/`); a draft's evidence and handout were listed as the chat's «site changes» (`NEWSROOM_FILES`); a settings save that changed nothing said «Saved and publishing» and failed (`applySettings()`); a cloud draft discarded during a job went from this copy only (now 409); the running box's word filter never matched a line, since every newsroom line opens with its clock (`progressLines()`); «Preview locally first» said nowhere where the preview was (the Desk shows its link); `--port=` on the command line (the Browser pane's launch.json opened 4777 while the desk took 7777). An independent review of the change then found nine smaller points, seven fixed (the build-failure alarm above, the 409 on discard never shown, a draft approved here and not yet sent tripping the alarm, an error with no text showing nothing, a file read after the answer had begun, Apply's partial failure reported as none). Looked at and left: unpublishing or discarding a cloud draft keeps its evidence and handout file in the repository; the chat's stream replays the thread on a reconnect; the editor's "actually doing work" line reads a run still in progress as short; a desk left open for days judges the live site by the newest story it last synced.
- Two gates at once fail each other (2026-11-13): the gate's build empties and refills `dist`, so a second `scripts/gate.mjs` or `npm run build` started in the same checkout (another session's Stop hook fires on the same stale files) makes both fail: one read 11,900 "broken links" from a half-built `dist`, the next stopped on `EPERM … dist\tags`. Before starting the gate, look for a running one (`node … scripts/gate.mjs`, `astro.mjs build`) and wait for it; a pass by either records the same `.gate/pass.json`. Under load (five model processes beside it) the build took 14 to 22 minutes where it takes about two.
- These notes were split (the owner, 2026-11-13: "slim CLAUDE.md to cut session cost without losing quality"): CLAUDE.md had reached 327,000 characters, about 100,000 tokens loaded into every session, every subagent and every cloud agent run (the editor, the issue agent, the control room's chat), each paying to write it to the cache again whenever a session started or sat idle past the cache's life. Every entry was moved word for word into `.claude/rules/*.md` (checked by script: no block of the old file is missing), each note scoped by `paths` so Claude Code loads it when a file it covers is read, written or edited (not on a search), and CLAUDE.md keeps what every session needs. `.gitignore` lets `.claude/rules/` into the repository so the cloud agents get the notes; the rest of `.claude/` stays local. Limits from Claude Code's memory documentation: an on-demand note longer than 40,000 characters is cut in a 200K-context session (150,000 at 1M), `@` imports load eagerly and save nothing, and a subagent other than Explore and Plan loads CLAUDE.md too.
